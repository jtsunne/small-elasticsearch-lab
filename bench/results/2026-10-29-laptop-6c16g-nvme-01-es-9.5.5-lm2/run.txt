generator: awk with srand(42), each message 110 draws of int(rand()*47)+1 over a list of 43 words (draws past 43 add an empty word, so messages contain double spaces; kept as run), piped to the loader on stdin; awk implementation not recorded (bench/l-m2.sh records it)
index: lm2, created by the first bulk request, dynamic mapping, defaults (1 shard, 1 replica that cannot be assigned on one node, refresh 1s)
loader: bulk, -clients 2, -bulk-size 1000, -input -, no retries needed
monitor: every 10 s, docker inspect state plus anon and file from memory.stat and memory.events inside the container; shmem and swap were not sampled
data_path: a directory on the host's /tmp, which is tmpfs (host.txt data_fs_type). The index files therefore lived in RAM, and the kernel charges tmpfs pages to the container's memory cgroup, where memory.stat counts them under file. The file values in the monitor files are index data in RAM plus page cache, not page cache over a disk. bench/l-m2.sh refuses tmpfs; repeat on a disk-backed directory before reading the memory split as page cache.
host_record: host.txt was captured with bench/host-info.sh on the same host about ten minutes after the run, not by the run itself; repo_commit there is dirty because of uncommitted documentation work, and the kernel build suffix was removed
